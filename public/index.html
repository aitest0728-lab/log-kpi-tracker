Per-District Staff Plan — by Weekday (Target Prod blank = target from Full_Cost_Planning.xlsx · Max OD % / Max Flex % blank = network default · headcounts blank = 0)

Definition. One FT Driver / FT Courier / PT Driver / PT Courier plan per weekday, per district (FTD / FTC / PTD / PTC). Blank = 0. Each column header shows how many times that weekday falls in the forecast month.
Per-weekday inputs. Each weekday cell carries its own Target Prod, Max OD % (Max Productivity Overdrive) and Max Flex % (Max ODS Volume Flex), so a leader can tune any single day without touching the rest of the week. Blank = the default (the district's Full_Cost_Planning.xlsx target / the network default ceiling).
Cell figures (below the dashed line). Σ = that day's total headcount. Orders = that day's forecast Total Order (HKTV shown beside it). Prod = that day's Productivity (HKTV Orders ÷ Σ) and its achievement rate against that day's target, (forecast − target) ÷ target. Cost/Ord = that day's Cost / Order against the district's target — green at or under target, red above.
Default = 0. Every cell starts blank (= 0) and stays that way until you type a number or run Suggest Headcount. With the plan empty the forecast shows the raw picture — no headcount, no staff cost, no minimum-roster charge.
These cells are the working plan. What you see here is the team the day's volume justifies, and the pill is the productivity that team is being asked for. Nothing is padded into the numbers.
FT roster pool (the 75%). An FT head works about 5–6 days in 7, so the commitment is 75% of the active FT bench × days in the month, held as a pool of FT man-days — not a fixed roster on every date. The plan spends that pool where the volume is: fewer FT on a quiet Wednesday, up to the full bench on a peak Friday, same payroll either way. Each cell shows the FT it rosters against the bench. Any pool man-days the month's volume can't absorb are charged to Variable — Staff at FT Unit Cost as one monthly line, so cost stays whole without parking idle heads on a date that has no work for them.
Overdrive and ODS Flex ceilings are set per district and per weekday — not one of each for the network. The two fields above are only the defaults; the Max OD % and Max Flex % fields in each weekday cell below override them for that district on that day alone. Suggest sweeps Overdrive up to the widest of a district's seven weekday ceilings, and each weekday stops climbing at its own. How much of each a district needs is a property of that district — its own bench, volume, unit rates, and ODS partner terms — so a district that needs 27% Overdrive can have it without leaning out the nine that already clear both targets at 0%, and a district whose Overdrive is spent (its team already fits inside the paid FT pool, so a leaner team changes no cost) can still be fixed by moving volume to or from ODS, which is a real cost change regardless of team size. Auto-Tune Overdrive & ODS Flex does this for you: it probes each district for the smallest Overdrive that clears both targets; where that alone isn't enough, it probes the smallest ODS Flex (holding Overdrive at whatever the first probe left) that closes the rest; and it writes only whichever of those actually moves the number, per district, leaving alone both the districts that already pass and the districts neither lever can fix. When a district misses, its badge says which — needs OD n%, needs ODS Flex n%, or OD/Flex won't help (the lever there is the FT bench or the target).
Both targets drive the search, not just one. A district is built at Overdrive 0% first — the leanest team that clears Target Productivity, capped by the Staff Allocation Cap. If that plan's Cost/Order already clears target too, it's used as-is. If not, Suggest re-builds the whole week at 1%, 2%, 3%… up to the Max Productivity Overdrive ceiling, and applies the smallest Overdrive that clears both — a leaner team both costs less and reads a higher Productivity, so the two targets pull the same way. The badge shows an OD n% pill whenever the search had to raise it above 0%. If nothing in the range clears both, the cheapest candidate found is applied and the badge explains why, in amber.
Per weekday, at whichever Overdrive the search is trying: staff = the leanest team whose Productivity lands between Target and Target × (1 + Overdrive %), capped by the Staff Allocation Cap. Driver : Courier = 49 : 51; already-paid FT-pool heads are used before any PT head is bought, then whichever type is cheaper.
Rostering across the week: the FT pool is then spread over the seven weekdays to cover as much of that demand as possible — a first pass learns what each weekday wants, a second re-plans each day inside its slice of the pool. FT inside the pool is already paid, so it is used before any PT head is bought and it is treated as free when the ODS/HKTV split is chosen. PT appears only where the pool is exhausted.
What gets written in: the deployed team from the chosen Overdrive, and only it — every head in the cells has work, so the Prod % in the badge, the cell pills and the Weekly Forecast Plan are all the same measurement. The undeployed part of the pool is reported under the badge as roster utilisation and charged as a monthly cost line, never as headcount.
ODS / HKTV split: each weekday's ODS volume is chosen within ±Flex% of its forecast baseline (and under the Max ODS % ceiling, if set) to minimise staff cost (actual roster) + ODS orders × Blended Cost/Order. Total Order volume is unchanged, so cheapest = lowest Cost/Order.
Cost check: run once per Overdrive candidate on the week — (Fixed + Staff + ODS) ÷ Est. Order Volume vs Target Cost/Order — as part of the same search, not as a separate pass afterward.
A plan is always applied. The badge reports both achievement rates and, in amber, which target it misses.

DistrictFixed ($)Variable — Staff ($)Man-days /wkStaff $/day (avg)Variable — ODS ($)Variable — ODS Tunnel ($)Total ($)Est. Order Volume /wkCost / Order ($)Target Cost / Order ($)Achievement (%)
Fixed = Provision Plan daily rate × days in the forecast week. Variable — Staff = Σ over weekdays of (that weekday's ACTUAL scheduled FT/PT plan × Unit Cost per head/day) × that weekday's occurrences in the week. Man-days /wk = the same sum in heads. Staff $/day (avg) = Variable — Staff ÷ days in week. Variable — ODS = ODS orders in force (after any split shift) × Blended Cost/Order. Variable — ODS Tunnel = ETH & WTH only (always $0 elsewhere): Σ over weekdays of (that weekday's ODS tunnel user count × $100/user) × that weekday's occurrences — the user count is that weekday's in-force ODS orders ÷ the district's own historical orders-per-ODS-user rate for that weekday, rounded up. Est. Order Volume /wk = Σ weekday Total Order forecast × that weekday's occurrences. Cost/Order = Total ÷ Est. Order Volume. Achievement (%) = (Cost/Order − Target Cost/Order) ÷ Target Cost/Order — negative is under target (green).
